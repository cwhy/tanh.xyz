Research note 01 · Reinforcement learning

Shared representations.

The environment produces experience. Fixed algorithms turn it into decisions and learning signals. Each learner predicts when queried and learns when given training data. Its loss and optimizer stay inside.

The complete graph

Every region belongs to the same system. The experience recorder stores, aligns, samples, and batches experience. Experience batches feed dynamics learning and target construction; the resulting targets plus experience feed actor and critic learning. Each learner contains its own loss and optimizer. Optional paths describe alternatives, not a single algorithm that uses everything.

One interface, several RL algorithms

This graph unifies reinforcement learning around functional roles and the data they use. It is a computation map, not a single algorithm: each method uses the functions, record types, and training objectives it needs. Actor, critic, and dynamics roles may share representations, parameters, and a joint training procedure.

Read the arrows

Single solid arrows carry data. Double-line arrows import a callable function: the destination supplies inputs and uses the returned result internally. Importing a function does not copy its parameters or train it. Dashed red arrows supply training data. Each learner computes its predictions, objective, gradients, and optimizer steps internally. Crossings are not junctions.

Select an action

The action selector receives the current state and can invoke the actor, the critic’s Q-function, or the planner. It samples from an actor distribution, selects from action values, or uses the planner’s returned action or distribution. These alternatives share the same action output and environment loop.

Plan with imported functions

The planner imports the learned dynamics function and, when needed, policy and value functions. It calls them on hypothetical states and actions to generate and score possible futures. The selector imports the planner itself, so its internal calls and returns need no additional prediction boxes.

Record once, batch inside the recorder

Current step data carries xₜ and, after an environment step, the preceding transition’s reward rₜ₋₁ and termination flag dₜ₋₁. Decision functions consume x; the recorder receives the step data and selected action. By retaining the previous state and action, it assembles (xₜ, aₜ, rₜ, xₜ₊₁, dₜ) when the next result arrives.

The recorder stores and aligns records, samples eligible transitions or sequences, and outputs an Experience batch. Sampling rules are internal to this fixed algorithm. The shared batch interface does not require all learners to use identical samples. Initial/reset observations start an episode; retain terminal observations before reset and never join records across episode boundaries.

One model-generated data interface

Model-generated data can contain predicted transitions, search policies, and value estimates. Dyna-style learning uses predicted transitions as training samples. MuZero uses search policies and value information alongside observed trajectories. These are different uses of one interface; an algorithm need not produce or consume every field.

The recorder can store a synthetic transition as a record or attach a search annotation to its matching environment timestep. Their sources remain explicit: a search estimate does not become an observed outcome because both are stored together. Search runs before the actual action and summarizes hypothetical futures.

Build targets, then learn

The target builder receives an Experience batch and imports the critic function. It evaluates the states or state–action pairs needed for returns, bootstraps, or advantages internally. The resulting Targets + experience package retains the samples and their appropriate learning signals.

The actor uses policy-learning signals such as advantages or search-policy targets. The critic uses return targets. The dynamics learner receives experience batches with the transition or sequence supervision its objective requires. Shared parameters may receive a joint update across these roles; separate arrows do not require independent optimizers.

Inside a learner: prediction and learning

predict(inputs) → outputs

Evaluate the current function without updating parameters. The caller chooses the input states or state–action pairs.

learn(training_data)

Compute predictions and the configured objective, differentiate, and apply optimizer steps. An appropriate objective and valid training signals are still required.

MuZero and shared representations

MuZero’s representation function h can live inside the learner roles: it maps observation history to a latent state. Dynamics g advances that latent state, and prediction f supplies policy and value outputs. Search repeatedly invokes these functions; latent states need not reconstruct future observations. Training unrolls dynamics along recorded actions and jointly supervises rewards, values, and policies. Schrittwieser et al., 2020.

Search-tree transitions are not automatically independent replay samples. Search policy and root-value annotations can instead accompany the corresponding observed trajectory. The graph captures this through the same Model-generated data interface used for synthetic transitions, while preserving their different training roles. DeepMind’s MuZero explanation.

A time-limit cutoff generally still permits bootstrapping from the final observation, although the advantage recursion must not continue into a reset episode. x means the state or history representation supplied to the learner; an observation alone need not be Markov.

Scope. Policy and value function imports are optional planner capabilities; an algorithm uses only the functions it requires. Networks may share parameters. Dynamics can be probabilistic or an ensemble. Learners encapsulate algorithm-specific objectives and autodifferentiation. Receiving arbitrary data does not guarantee learning or improvement: the training call needs a specified objective, appropriate data, and an optimization rule. Those are hidden inside the module, not assumed to disappear. A fixed algorithm can call a learned function without itself becoming a learned network.
